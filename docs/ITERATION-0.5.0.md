## 简历编辑

- 保留模块编辑，在内容上方提供加粗、列表、小标题与表格按钮，修改当前选区或所在行。
- Ctrl+Z / Ctrl+Y 撤销重做，连续输入合并，会话最多保留 40 组；更多菜单也提供按钮。
- 每份简历保留最近 20 个 gzip 历史版本。编辑前的自动检查点每 5 分钟最多一次，也可手动保存。可恢复或复制为新简历，恢复前保存当前稿。删除简历会删除历史；投递记录中的独立快照继续保留。
- 导出前实际生成 PDF，读取真实页数，渲染缩略图并检测疑似空白页。展示前 6 页，检测覆盖最多 60 页；另提示预览中可能横向溢出的条目。导出复用检查过的文件。
- 空白检测是像素启发式，条目分页衔接仍需查看。实时 A4 容量提示继续属于估算。

## 岗位定制

入口为工作台更多菜单的“岗位对照”和职位卡片的“针对岗位制作简历”。支持选择基础简历、收藏岗位或直接粘贴职位要求。

本地规则识别 C/C++、Linux、RTOS、MCU、ARM、驱动、外设及网络通信、调试、LVGL 等技术与学历关键词，列出职位原文和简历依据，缺项标为待确认。相关表述不等于满足熟练度要求，不生成 ATS 分数，也不覆盖所有语义要求。本地建议调整平铺技能条目顺序，保留既有事实。

在线建议逐模块显示原文、建议与理由，用户逐项选择后生成独立岗位简历，原稿保留。在设置填写完整 Chat Completions 地址、模型和密钥。密钥按 Windows 当前用户加密，不进入普通设置 JSON、简历备份或后端日志。外部接口需 HTTPS，本机模型可用 loopback HTTP。不跟随重定向、不自动重试，支持取消等待。

只有主动点击“获取 AI 建议”才发送职位描述、求职意向和可见模块；姓名、电话、邮箱、照片字段不发送。模块内自行填写的个人信息仍会发送，界面会提示发送范围与可能费用。建议必须对应原模块，拒绝重复／越界模块、HTML、过长内容和新增数字。此检查不能保证所有事实真实，技能、职责与成果仍需用户核实。

请求使用 `model`、`messages` 与 `choices[0].message.content`，格式依据 [OpenAI Chat Completions 官方说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。不同兼容服务的模型名称、支持情况和额度由其服务决定。

## 投递管理

- 增加笔试中进度；状态与安排时间变化记录时间线。旧记录下次修改时开始记录，不追补不存在的历史。
- 保存下一次笔试、面试、跟进或截止安排，支持标记已处理、备注和复盘。
- 应用运行时每分钟检查，提前 24 小时及到期各提醒一次；重新打开补查未处理事项。关闭应用时不发后台通知，已录用／已结束不提醒。
- 确认实际使用的简历后固定完整投递快照。快照不被后续简历编辑或状态更新覆盖，可查看并复制成新简历。
- 旧记录只有名称时显示尚无快照，不把当前简历伪装成过去投递内容。旧客户端保存也不会抹去时间线、快照和新增安排字段。

## 验证与边界

Java 离线工作流检查覆盖压缩历史、数量限制、重启读取、路径约束、旧记录兼容、时间线与快照；原有职位解析检查继续运行。客户端 `--feature-test` 使用隔离数据验证原生编辑、历史 API、本地对照、独立岗位版本、模拟 AI 协议与联系人字段排除、数字约束、密钥加密、投递快照和提醒，并读取实际单页／多页 PDF。

真实在线 AI 服务、原站投递、人工文件选择器和其他 Windows 设备仍需验收；没有密钥时用模拟服务验证，不宣称真实模型调用成功。

本机验证结果：Java 严格编译和 WinUI Release 构建 0 警告、0 错误；16 项离线持久化工作流检查、13 项职位详情解析检查及原有官网结构化解析检查通过。23 项桌面功能检查和 9 项界面回归通过，包含原生岗位简历生成弹窗、投递编辑弹窗、PDF 检查弹窗、单双页 PDF 渲染、双界面及预览复用。查看了原生界面截图和 PDF 页图；原生 RenderTargetBitmap 不含 WebView2 预览区域，PDF 另行渲染核对。
